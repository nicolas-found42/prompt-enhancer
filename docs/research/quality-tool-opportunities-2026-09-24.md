# Additional quality tools for Prompt Enhancer

Research date: 2026-09-24. This is a recommendation inventory, not a change to the checks. Community [pre-commit](https://github.com/cleder/awesome-pre-commit-hooks), [static analysis](https://github.com/awesome-security/awesome-static-analysis), [frontend](https://github.com/codesandtags/frontend-resources), [Vite](https://github.com/vitejs/awesome-vite), and [GitHub Actions security](https://github.com/johnbillion/awesome-github-actions-security) lists supplied candidates. Every capability and usage recommendation below is checked against its project's documentation or source. Ranking reflects this repository's gaps and likely maintenance cost, not a benchmark of the tools.

## Existing baseline and selection rule

The current [pre-commit configuration](../../.pre-commit-config.yaml) already checks `uv.lock`, runs staged Ruff and Prettier/ESLint fixes, and runs whole-project Ruff, ty, TypeScript/Vite build, pytest with an 80% coverage floor, and Playwright. The [CI workflow](../../.github/workflows/checks.yml) runs all hooks plus the optional CatBoost test. Python uses [uv/Ruff/ty](../../pyproject.toml); web uses [ESLint/Prettier/TypeScript/Playwright](../../web/package.json). The web app has nine browser tests but no dedicated fast component/unit suite or JavaScript coverage gate. These observations come from the checked-in files, not the discovery lists.

Add tools only when they detect a distinct failure mode. Keep quick staged-file checks in pre-commit; use CI for network calls, browser work, full-history scans, or checks with notable startup cost. CI already repeats the local hooks, so a new local hook should also run in CI through the existing workflow.

## Candidates to defer or avoid

- **A second Python formatter/type checker or broad lint bundle:** Ruff and ty already own these roles; adding Black, isort, mypy, or a generic "super-linter" would duplicate signal and create disagreement. Ruff can enable selected [security (`S`) rules](https://docs.astral.sh/ruff/rules/#flake8-bandit-s) after reviewing findings; blanket `S` also flags ordinary test assertions (`S101`), so scope and per-file exceptions matter.
- **`pip-audit` beside `uv audit`:** PyPA documents useful environment and requirements scans, but native uv already audits this lockfile's dependency groups/extras. Keep pip-audit as a fallback if uv's preview audit is unsuitable. [pip-audit](https://github.com/pypa/pip-audit), [uv audit](https://docs.astral.sh/uv/reference/cli/#uv-audit)
- **More browser engines or snapshot coverage gates immediately:** Current Playwright tests already run Chromium. Add Firefox/WebKit only for a concrete compatibility promise; visual snapshots require stable review baselines. [Playwright projects](https://playwright.dev/docs/test-projects), [visual comparisons](https://playwright.dev/docs/test-snapshots)
- **New mandatory scans without baseline triage:** Network advisories, rule updates, and optional-dependency imports can produce unrelated failures. First run the tool, review each finding, document narrow exclusions, then make the job required. This is a workflow recommendation based on the stated behavior of [uv audit](https://docs.astral.sh/uv/reference/cli/#uv-audit), [npm audit](https://docs.npmjs.com/cli/v11/commands/npm-audit/), and [deptry](https://deptry.com/).

## Suggested sequence

1. Add hygiene and `actionlint` hooks; apply explicit read-only Actions permissions; then run all hooks locally and in CI.
2. Run `zizmor`, `uv audit`, and `npm audit` as separate, visible CI checks after reviewing initial findings. Enable update PRs to keep findings actionable.
3. Add one axe accessibility test and targeted Vitest/Hypothesis tests. Set web coverage thresholds only after those tests cover meaningful behavior.
4. Trial `deptry` and optional Ruff `S` rules as reviewed source-quality changes, not a large unexamined rule flip.

No candidate was installed or benchmarked for this note. A local networked `uv audit --locked` check completed in about 0.6 seconds and reported no known vulnerabilities or adverse statuses across 62 packages; it printed the experimental warning. A local `npm audit --audit-level=high` check also reported zero vulnerabilities. An offline uv probe stopped because OSV data was not cached. Other proposed scanners' baseline findings remain unverified.
