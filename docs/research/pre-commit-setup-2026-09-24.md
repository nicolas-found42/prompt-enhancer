## First-party guidance and recommended shape

1. **Use repository-local, system-language hooks.** Pre-commit supports `repo: local`, including hooks coupled to a repository's environment, and documents `entry`, `language`, `files`/`types`, `pass_filenames`, and `always_run`. Staged format/lint hooks can receive filenames; whole-project type checks and tests should use `pass_filenames: false` and `always_run: true`. Its Git hook runs against staged content, temporarily stashing unstaged changes. ([pre-commit: local hooks and hook fields](https://pre-commit.com/#repository-local-hooks), [pre-commit: Git pre-commit behavior](https://pre-commit.com/#pre-commit))
2. **Call Python tools with `uv run`.** uv runs commands in the project environment and checks its lock/environment for consistency. Ruff's formatter writes only the paths passed to `ruff format`; `ruff check --fix` can repair staged-file lint violations. Ruff says its formatter does not sort imports, so enable import sorting as a linter rule if wanted, before formatting. ty's documented command is `ty check`, with paths supported for selecting the repository's `src scripts` scope. ([uv: running project commands](https://docs.astral.sh/uv/concepts/projects/run/), [Ruff formatter](https://docs.astral.sh/ruff/formatter/), [Ruff linter](https://docs.astral.sh/ruff/linter/), [ty type checking](https://docs.astral.sh/ty/type-checking/))
3. **Make web formatting a project dependency and script.** There is presently no web formatter or linter command. Prettier documents `--write` for selected files, `--check` for verification, and `--ignore-unknown` for mixed file lists; it recommends a configuration file so the CLI and editors agree. Add Prettier and, for a lint check distinct from TypeScript, ESLint with an explicit project config/script. This is a new policy choice and may expose baseline violations. ([Prettier CLI](https://prettier.io/docs/cli), [ESLint configuration files](https://eslint.org/docs/latest/use/configure/configuration-files))
4. **Keep whole-project checks behind staged checks.** The repository's `npm run build` already checks TypeScript and builds with Vite. Playwright's `npx playwright test` runs all configured tests, and browser binaries may need a separate install after dependency setup. The local configuration also needs the root `.venv` and starts web/API servers, so it is materially heavier than a staged file check. ([Playwright CLI](https://playwright.dev/docs/test-cli), [Playwright browsers](https://playwright.dev/docs/browsers), [`web/playwright.config.ts`](../../web/playwright.config.ts))

## Implementation details to verify

- Add the pre-commit package through uv's dev dependency group, install the hook with `pre-commit install`, then run `pre-commit run --all-files`. Pre-commit documents both commands. ([pre-commit quick start](https://pre-commit.com/#quick-start))
- Run staged Python lint/format before whole-project ty and pytest. Run staged web formatting/lint before the web build and Playwright. The hook entries should use the project's `uv run` and `npm`/`npm exec` commands, rather than floating global tool versions. ([uv project commands](https://docs.astral.sh/uv/concepts/projects/run/), [pre-commit local hooks](https://pre-commit.com/#repository-local-hooks), [Prettier local CLI](https://prettier.io/docs/cli))
- Expect a first formatter pass to change existing files if their style differs. Review those diffs; do not silently skip failing existing tests or type checks. Ruff and Prettier both document in-place formatting behavior. ([Ruff formatter](https://docs.astral.sh/ruff/formatter/), [Prettier CLI](https://prettier.io/docs/cli))
- The checkout currently has modified tracked Python bytecode and an untracked local settings file. Preserve those unrelated files when staging or committing the hook setup. This is a working-tree observation, not a tool-doc claim.
