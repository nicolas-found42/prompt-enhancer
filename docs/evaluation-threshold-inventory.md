# Jev decision and threshold inventory (2026-09-23)

Jev receives `model`, `state`, and named typed `questions` through the OpenRouter Decisions API. A `noul` answer contains its yes probability (`noul`); the observed recordings do not contain a separate confidence value. The parser derives `max(p, 1-p)` where the product expects a confidence field. Thus a high yes cutoff plus `confidence >= 0.8` is one probability gate, not two independent signals. This matches the [OpenRouter Decisions API example](https://openrouter.ai/blog/tutorials/how-to-use-jev/) and [prompt-to-questions batching example](https://openrouter.ai/labs/jev/compile). The batch builder names the relevant `state.items[key]` in each question; the observed replays parsed without a transport fault.

| Question or decision family | Current cutoff | Matching gold and status |
| --- | --- | --- |
| `gap:context`: “Is the required piece 'relevant context' confidently missing from the request?” | 0.87, exact wording only | Earlier SOAR mixed-turn split had 118 train and 32 holdout. A cleaner first-turn development/independent-holdout audit found very low recall at 0.87; lowering the cutoff caused many false flags. The default is provisional; see [results](evaluation-results-2026-09-23.md). |
| `gap:goal`, `gap:constraints`, `gap:output_format`, `gap:done_criteria`; task-specific `gap:sources`, `gap:language`, `gap:tests`, `gap:time_horizon` | 0.90 each | No defensible matching real-prompt gold yet. The private review form asks for these keys with source-session context. ClarifyCodeBench can test `output_format` separately on controlled coding edits. |
| `pointer:{kind}:{window}` for vague, unresolved-reference, contradictory, and embedded-instruction sentence selection | choice confidence 0.80 | Needs human sentence span and kind labels. Prompt-level gap keys do not validate a sentence pointer. |
| `problem:{kind}:{sentence}` for the four sentence problems | yes probability 0.90, derived confidence 0.80 | Needs human sentence-level true/false judgments on the selected sentence and suitable negatives. |
| `infer:{gap}` value or `unknown` | selected option probability and choice confidence 0.80 each | Needs user-confirmed answer values, not a model's proposed answer. |
| `faithful:{test}`: “Is this proposed success test faithful to the user's request, and does it test success rather than an invented requirement?” | yes probability 0.90, derived confidence 0.80 | Needs human judgments of each proposed success test against the full request. The current SOAR replay has 477 proposals and only 23 accepted tests; this is an attrition observation, not a precision estimate. |
| `strategy_choice` and `strategy_recheck:{strategy}` | priority choice; recheck yes probability 0.80 | Needs human strategy-appropriateness judgments for the exact prompt and confirmed gap. |
| `meaning_preserved`, `no_invention`, `edits_confined` candidate fidelity questions | yes probability 0.80 each | Needs human comparison of original and candidate; no candidate in the SOAR set reached these gates. The pilot candidate failed `meaning_preserved` (0.70) and `edits_confined` (0.74), and the strong model was therefore not run on it. |
| Output grading against prompt-specific success tests | pass probability 0.50 | Needs human judgments of actual model outputs against faithful tests. There is one scored pilot case, insufficient for calibration. |
| Assumption-edit meaning preservation | yes probability 0.80 | Needs human original-versus-edited-prompt judgments. |
| Adopted custom rubric questions | stored per-question threshold (writer suggestion starts at 0.80) | Each exact wording needs its own labeled training/holdout set before adoption. |

Threshold changes must be selected on training data and reported on untouched holdout data. Split prompts from one conversation or study participant together. Do not reuse the 0.87 `context` cutoff for any other question or wording. The [source follow-up](evaluation-source-followup.md) found no newly ready public broad prompt-gap labels, and the [private review tool](../scripts/human_gap_review.py) prepares the missing prompt-level judgments. The remaining question families require separate human annotations of tests, sentences, answers, candidates, and outputs before they can be called calibrated.
