# Jev decision and threshold inventory (2026-09-23)

Jev receives `model`, `state`, and named typed `questions` through the OpenRouter Decisions API. A `noul` answer contains its yes probability (`noul`); the observed recordings do not contain a separate confidence value. The parser derives `max(p, 1-p)` where the product expects a confidence field. Thus a high yes cutoff plus `confidence >= 0.8` is one probability gate, not two independent signals. This matches the [OpenRouter Decisions API example](https://openrouter.ai/blog/tutorials/how-to-use-jev/) and [prompt-to-questions batching example](https://openrouter.ai/labs/jev/compile). The batch builder names the relevant `state.items[key]` in each question; the observed replays parsed without a transport fault.

| Assumption-edit meaning preservation | yes probability 0.80 | Needs human original-versus-edited-prompt judgments. |
| Adopted custom rubric questions | stored per-question threshold (writer suggestion starts at 0.80) | Each exact wording needs its own labeled training/holdout set before adoption. |

Threshold changes must be selected on training data and reported on untouched holdout data. Split prompts from one conversation or study participant together. Do not reuse the 0.87 `context` cutoff for any other question or wording. The [source follow-up](evaluation-source-followup.md) found no newly ready public broad prompt-gap labels; the user's delegated model judgments now supply an explicitly model-labeled prompt cohort. The remaining question families need direct labels of sentences, inferred values, strategies, candidates, or outputs. Prompt-level gap labels alone cannot calibrate those gates.
