# Automatic Jev question rewording

`RubricRevisionService.reword(gateway, question_id, dataset, attempt_id=...)` is an explicit, noninteractive maintainer entry point. It returns `adopted`, `hold`, or `reject`, stores the full decision, and changes the active rubric only when every adoption gate passes. An ordinary Optimize request only reads the active rubric.

The dataset is a mapping with `rows`. Each row has a stable `id`, a source `group_id`, a `partition` (`training`, `calibration`, `final`, or `regression`), the Jev `state`, an independent `label`, and `provenance` (`human`, `source`, or `deterministic_synthetic` for automatic final validation). `weak` and `delegated` labels remain identified but cannot promote a candidate. A source group must occur in only one partition. Noul labels are booleans for the rubric's **missing** event; the workflow complements Jev's Noul probability when `missing_when` is `no`. Choice labels name one ordered option; Score labels are level indexes. Choice and Score datasets also provide ordered `criteria` at the top level. Unsupported shapes and invalid labels fail before inference.

The writer sees the current question and training rows only. Jev screens each alternative against the original condition, options or levels, new requirements, and evaluator steering. Code accepts supported alternatives, compares group-fold training Brier loss with the unchanged baseline, and fits a new threshold on calibration rows through the versioned #50 gate policy. For the current active Noul rubric, final promotion requires at least 30 independent final groups and five examples of each outcome. The workflow opens the sealed final rows only for the selected alternative and baseline. A seeded paired group bootstrap lower bound must exceed 0.01 Brier units and the stability floor from paired repeat predictions, precision and recall must not regress, pinned regression examples must not acquire new failures, and the incremental evaluation cost must stay within the policy. The final result records every gate and its measurements. Choice uses multiclass Brier, and Score uses normalized cumulative ordinal Brier; automatic promotion holds until a matching nonbinary calibration mapping is available.

Provide paired repeats in `repeat_answers`, keyed by the SHA-256 digest of each wording's canonical JSON text and then final row ID. Each entry contains `snapshot` and a raw Jev `raw_answer` from a distinct repeat of the same wording and state. Missing or incomplete repeat evidence holds promotion. The stability floor is the paired difference in Brier loss, never raw probability spread.

By default, one invocation allows one writer proposal, up to four alternatives, 5,000 metric evaluations, and $0.25 of reserved paid work including retries. Live work requires catalog pricing for both writer and Jev. Scripted and strict replay gateways can run without paid pricing. Exact question, state, criteria, version, and answering snapshot keys cache raw evaluations in SQLite. Final validation digest consumption is durable; a new attempt ID cannot reuse the same revealed holdout. Repeating the same attempt ID returns its stored result without new calls. Successful adoption writes an immutable rubric version with a new question version, refitted threshold, and calibration snapshot. `SQLiteRubricStore.rollback_reword(version_id)` restores its immediate parent when that automated version is still active.

The audit contains raw screening and evaluation answers, answering snapshot, split IDs and label provenance, baseline and candidate hashes, budget usage, and the gate results. Scripted examples prove the workflow and replay contract; they do not establish real-world wording gains. A hold caused by missing independently labeled data is a complete workflow outcome and does not request new labels as an implicit prerequisite.
