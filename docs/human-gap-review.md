# Human gap review for the private agent-session batch

**Status:** The user delegated both pending judgments to Codex and directed
that they be treated as project ground truth. The completed model review is
stored privately as `.local/evaluation/prompt-gap-delegated-review.json`; the
100-test faithfulness sheet is completed and audited at
`.local/evaluation/faithfulness-delegated-review.csv`. Both outputs explicitly
say `user_delegated_model`, so they are not represented as human annotations.
The 139-case public real-prompt cohort supplies the requested 100–200 gap
judgments. The offline form below remains available only for optional future
human validation; using the app does not require this review process.

The corrected batch at `.local/evaluation/local-agent-review-batch.json` contains 150 real user turns from 150 distinct Codex, Claude Code, and oh-my-pi sessions. Its historical assistant results show what happened, but are **not** gap labels or correctness judgments. The local form is generated by [`scripts/human_gap_review.py`](../scripts/human_gap_review.py) and contains private text; keep the form, export, and imported dataset under ignored `.local/evaluation/`.

```sh
uv run python scripts/human_gap_review.py prepare \
  --batch .local/evaluation/local-agent-review-batch.json \
  --output .local/evaluation/human-gap-review.html
```

Open the HTML file locally in a browser. Enter a human reviewer name or initials. For each case, inspect the **source session** named in the form before deciding what context the original assistant had. Mark a prompt `standalone` only when its request can be judged as written; if relevant earlier turns are needed, paste the exact relevant text into `context_text` and mark `reconstructed`. Exclude cases whose necessary files, images, repository state, or prior conversation cannot be recovered. Do not call missing standalone information a `context` gap if the original agent already had it. The historical assistant result can help locate the task; do not infer a label solely from its success or failure.

Apply gap labels to the effective prompt shown to the optimizer, including reconstructed context when used. A gap is a **materially required** piece that the user did not provide and cannot be safely inferred. An empty checked set means an explicit judgment that none of the applicable checklist gaps is present. Mark uncertain cases for adjudication rather than choosing a likely label.

| Key | Label only when… |
| --- | --- |
| `goal` | The requested outcome itself cannot be determined. |
| `context` | Essential background or the object to operate on is unavailable in the effective prompt and original session. |
| `constraints` | A material boundary or requirement is absent, rather than merely optional detail. |
| `output_format` | The task requires a specific deliverable form that is missing. Do not label ordinary flexible prose. |
| `done_criteria` | The user requires a completion condition, and the condition is missing or untestable. |
| `sources` | An analysis or research task needs a source basis that is unavailable. |
| `language` | A coding task needs a language or runtime and it cannot be inferred from supplied code or context. |
| `tests` | A coding task needs test expectations beyond what the request or existing repository provides. |
| `time_horizon` | A planning task needs a relevant deadline or planning span that is missing. |

Choose the task type that best describes the effective request: `general`, `writing`, `analysis`, `research`, `coding`, `planning`, or `chat`. Save progress with **Download review JSON** and load that export into the form to continue. The page makes no network requests. When at least 100 cases are complete and usable, import the export:

```sh
uv run python scripts/human_gap_review.py import \
  --batch .local/evaluation/local-agent-review-batch.json \
  --review .local/evaluation/prompt-gap-human-review.json \
  --output .local/evaluation/local-agent-human-labeled.json
```

The importer validates batch identity, source-session review, allowed keys, exact reconstructed context, and the 100-case minimum for this standalone human form. It retains reviewer provenance and task strata, including empty gap lists as labeled negatives. Reconstructed text remains private. Fewer than 100 private cases may be usable after context exclusions; the separately reviewed 139-case public cohort supplies the count for requirement 59. Split related source conversations together during threshold tuning and keep a held-out group untouched.

Prompt-level labels can tune the `gap:*` questions. The [threshold inventory](evaluation-threshold-inventory.md) lists the additional human judgments needed for sentence, test-faithfulness, inference, fidelity, grading, and strategy cutoffs. Those decisions need their own evidence; prompt-level labels do not imply them.

## Success-test faithfulness review

The second prepared artifact, `.local/evaluation/faithfulness-human-review.csv`, contains 100 proposed success tests from first-turn SOAR cases: 50 from each writer. The sheet hides Jev's scores so they cannot bias the reviewer. For each row, compare the proposed test to the prompt **as shown**, fill `human_faithful` with `yes`, `no`, or `uncertain`, and record `human_reviewer` and `reviewed_at` (ISO date). `yes` means the test measures something the user actually requested without adding a requirement. Use `uncertain` where source redaction or task context makes that impossible to judge. Keep this CSV private because SOAR does not declare a redistribution license.

The separate ignored `.local/evaluation/faithfulness-review-evidence.json` contains the recorded Jev probabilities and hashes of the prompt/test text. Once the human sheet is complete, the validator checks that the source text was not edited, groups both writers' tests from each source conversation in one split, and requires at least 80 yes/no judgments before reporting a trained cutoff and holdout result:

```sh
uv run python scripts/calibrate_faithfulness.py \
  --review .local/evaluation/faithfulness-human-review.csv \
  --evidence .local/evaluation/faithfulness-review-evidence.json \
  --output .local/evaluation/faithfulness-calibration.json
```

The delegated audit produced 99 definite yes/no judgments. Its source-group
holdout supported a conservative 0.80 effective gate rather than the 0.73
training-selected threshold. The changed downstream ROPE paths were rerun
live and strictly replayed. Human validation would be a separate future study,
not a prerequisite to using the completed app.
