# Public human gap labels: source follow-up (2026-09-23)

The [evaluation data inventory](evaluation-data.md) already identifies SOAR Lab as the usable real developer-prompt gap set, ClariQ as a clarification-need set, and ClarifyCodeBench as a controlled coding set. I looked for an **additional public set of spontaneous user prompts with human labels for actual omissions or ambiguities** across the optimizer's task types. I did not find one that is ready to add to the primary per-gap benchmark. The following are the closest new leads; this is a finding about the sources checked, not proof that no such dataset exists.

| Source | Prompt provenance and released evidence | Fit and disposition |
| --- | --- | --- |
| [ROPE user study](https://github.com/mqo00/rope) | The authors release [300 prompt rows](https://github.com/mqo00/rope/blob/main/study_material/user_study_prompts.csv) from 30 participants (verified against the CSV): 120 `original`, 30 `iterated`, and 150 `optimized` rows. The first two groups are participant-written prompts for six fixed game and assistant tasks; the optimized rows are separate and should not be treated as spontaneous input. The repository also releases [reference requirements and task rubrics](https://github.com/mqo00/rope/blob/main/study_material/reference_reqs_prompts.pdf) under a repository [Apache-2.0 license](https://github.com/mqo00/rope/blob/main/LICENSE). The [paper](https://doi.org/10.1145/3731756) says researchers scored whether each reference requirement was correctly expressed, including omission and commission defects. | Strong **seed for new human review**, especially `goal`, `constraints`, and `done_criteria` on the fixed tasks. The public CSV has no per-prompt defect labels or scored requirement matrix, only prompt text and metadata. Its 150 participant-written rows do not yield 150 already labeled examples; task diversity is narrow. It cannot establish missing facts outside each provided reference task. |
| [PELS prompt quality dataset](https://aikosh.indiaai.gov.in/home/datasets/details/pels_prompt_engineering_literacy_scale_dataset_for_prompt_quality_assessment.html) | The publisher lists prompt text, domain, six expert rubric scores, weighted score, and human justification in an open MIT-licensed XLSX. It says prompts come from public prompt repositories and original team-written prompts. | **Inspect before use.** The listing does not identify each row's original author/source, define C1–C6 in enough detail to map them to actual gap keys, or establish that the prompts were spontaneous user requests. Quality scores cannot be converted into `context`, `output_format`, or other binary gap truth by a numeric cutoff. The mixed provenance also requires a per-row audit. |
| [Ambiguity Handling in User Queries](https://huggingface.co/datasets/razbit96/Ambiguity-Handling-in-User-Queries) | The creators release 251 real Reddit advice posts and human clarifying comments across 14 subreddits, with multiple human judgments of each **response's** clarification type, helpfulness, and preference. Collection required at least one clarifying comment; the [dataset card](https://huggingface.co/datasets/razbit96/Ambiguity-Handling-in-User-Queries) lists no license. | Useful as an advice-domain **question-quality** probe after license review. It lacks labels on what is missing from each original post, and selection for an existing clarification removes ordinary negative examples. A fact-based clarifying reply is evidence about a reply, not a gold `context` gap in the prompt. |
| [10k Prompts Ranked](https://huggingface.co/datasets/data-is-better-together/10k_prompts_ranked) | 10,331 prompts have community human 1–5 quality ratings. Source metadata distinguishes synthetic and human-generated prompts and names underlying sources, including ShareGPT and OpenAssistant; the [card](https://huggingface.co/datasets/data-is-better-together/10k_prompts_ranked/blob/main/README.md) marks the license as needing more information. Most entries have only one or two ratings. | Can support prompt-quality ranking research after source filtering, but the ratings give **no gap type, missing detail, or required clarification**. Synthetic and evolved prompts must be excluded for real-prompt evaluation. It cannot calibrate checklist precision or recall. |
| [CLAIRE](https://www.ims.uni-stuttgart.de/en/research/resources/experiment-data/clarifying-insertions-from-revision-edits-claire/) | The University of Stuttgart describes real wikiHow instructional sentences paired with candidate insertions, each human-rated for plausibility. | Relevant to whether a proposed clarification is plausible. These are edited how-to texts, not users' requests to a chat assistant; the label is insertion plausibility rather than whether a checklist gap exists. |

Two additional results were checked but do not change the conclusion: the [AI Observatory annotations](https://huggingface.co/datasets/aiobservatory/annotations) cover real conversations and task taxonomy, but its authors release **annotations only**, with no redistributed prompt text or gap labels; [UID](https://doi.org/10.1016/j.neucom.2024.128046) describes real user instructions and human revisions in a writing-specific setting, but the paper's public page does not provide a downloadable per-prompt gap dataset or a license. Its revisions should not be assumed to encode the optimizer's checklist keys.

**Recommended next step:** use SOAR's source labels only for questions whose meaning matches them, keep ClariQ and controlled sets as separate metrics, and have reviewers label the existing [150-case local coding-agent batch](evaluation-data.md#local-coding-agent-sessions) for the remaining keys. ROPE participant-written prompts are an optional, public, fixed-task supplement once reviewers have task references and add explicit per-prompt labels. Keep session context alongside local agent prompts; otherwise a reference to a file or previous turn may look like a `context` gap when it was supplied elsewhere.
